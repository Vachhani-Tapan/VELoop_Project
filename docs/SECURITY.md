# Security & Anti-Cheat Enforcement Matrix

This document maps all business-critical security and anti-cheat requirements directly to their concrete implementation in code.

| Threat Vector | Attack Scenario | Mitigation Strategy | Location in Codebase |
| :--- | :--- | :--- | :--- |
| **Client-Side State Manipulation** | Attacker edits React dev tools state to make Day 7 claimable. | The frontend sends no day or reward value. If sent in body, the backend completely ignores `req.body.day` and derives the actionable day strictly from `StreakCycle.currentDay`. | [`src/services/streak.service.js`](../backend/src/services/streak.service.js#L205) (`eligibleDay = cycle.currentDay`) |
| **System Clock Tampering** | User adjusts device clock forward 24h to bypass the wait period. | Timestamps (`nextClaimAt`) and time comparisons use the server's authoritative UTC clock (`getServerNow()`). Client time is never trusted. | [`src/utils/clock.js`](../backend/src/utils/clock.js)<br>[`src/services/streak.service.js`](../backend/src/services/streak.service.js#L209) |
| **Simultaneous / Double Claims** | Attacker fires 20 simultaneous `POST /claim` requests at the same millisecond. | Compound unique index `(userId, cycleId, day)` on `StreakClaim` prevents concurrent writes. Transaction rolls back and returns `409 ALREADY_CLAIMED`. | [`src/models/StreakClaim.js`](../backend/src/models/StreakClaim.js#L27)<br>[`src/services/streak.service.js`](../backend/src/services/streak.service.js#L402-L456) |
| **Day-Skip Exploit** | Attacker calls `/claim` requesting Day 5 while on Day 1. | Day progression is strictly sequential: `cycle.currentDay` advances only by +1 per verified claim. Day 5 is structurally unreachable without prior claims for Days 1–4. | [`src/services/streak.service.js`](../backend/src/services/streak.service.js#L423) |
| **Forged Reward Value** | Attacker sends `{ amount: 100000, currency: "INR" }` in claim payload. | Reward values and currencies are fetched directly from the backend's `StreakReward` collection in MongoDB Atlas, ignoring client body. | [`src/services/streak.service.js`](../backend/src/services/streak.service.js#L249) |
| **Cross-User Hijacking** | User A tries to claim on behalf of User B (`{ userId: "UserB" }`). | `userId` is extracted exclusively from the cryptographically verified JWT (`req.user.userId`). Payload user IDs are ignored. | [`src/middleware/auth.js`](../backend/src/middleware/auth.js#L32) |
| **Wallet Race Conditions** | Concurrent credits corrupting balance due to read-modify-write. | All balance increments execute via MongoDB's atomic `$inc` operator within database transactions. | [`src/services/wallet.service.js`](../backend/src/services/wallet.service.js#L37) |
| **Replay & Double Credit** | Network glitch re-sends successful claim transaction. | Unique deterministic reference IDs (`STREAK-<cycleId>-<day>`) on `WalletTransaction` ensure ledger idempotency. | [`src/services/wallet.service.js`](../backend/src/services/wallet.service.js#L30) |
| **Missed Day Detection** | User misses claim by 24h+ and tries to resume old streak. | On every read and claim attempt, `checkMissedWindow()` checks if `now > nextClaimAt + graceHours`. If missed, cycle is marked `RESET` and Day 1 begins. | [`src/services/streak.service.js`](../backend/src/services/streak.service.js#L100-L145) |
| **Rate-Limiting & Anti-Spam** | Rapid automated bot hammering on `/claim`. | `express-rate-limit` limits claim attempts per IP to 10 per 15 minutes in production. | [`src/routes/streak.routes.js`](../backend/src/routes/streak.routes.js#L24) |
| **Information Leakage** | Database errors leaking stack traces or schema structures to client. | Centralized Express error handler catches all exceptions, suppresses Mongo driver errors and stack traces, and returns sanitized `{ success: false, message, code }`. | [`src/middleware/errorHandler.js`](../backend/src/middleware/errorHandler.js) |
